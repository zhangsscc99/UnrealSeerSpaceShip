# Fix Plan — 中央园区整体等比放大 2 倍（面积 ×4）

## 目标（已与用户确认，不要改口径）

把中央园区**整体等比放大 2 倍**：地面铺装、围墙、亭台楼阁、假山、树木、水面——
**位置与尺寸全部 ×2**，三个轴都乘 2。等比，不失真。地面面积随之变成 4 倍。

用户是在明确对比后选的"等比"：**不是**"建筑保持原尺寸、只把场地铺开"。不要做后者。
更早一次"把装饰物撒到远处撑大包围盒"的做法也被否掉了。要的是中央园区本身变大。

判定标准：中央园区 X/Y 跨度变为当前的 2 倍（基线 xspan 9105.3 / yspan 9240）。

## Phase 1 —— 一次相似变换（核心步骤，一个脚本）

设园区中心 **C = (167.3, 160.0)**，Z 绕 **z=0** 缩放。对每个入选 actor：

```
新位置.x = 167.3 + 2 × (旧位置.x − 167.3)
新位置.y = 160.0 + 2 × (旧位置.y − 160.0)
新位置.z = 2 × 旧位置.z
新缩放   = 旧缩放 × 2          # 三个轴都 ×2（等比，不失真）
```

**为什么绕同一个 C 等比缩放是安全的**：这是相似变换，任意两个 actor 的相对关系
（相邻、相接、重叠、间距）被**精确保持**。铺装板块之间不会出现缝隙，墙仍相接，
**不需要重新贴地、不需要补缝**。Z 绕 z=0 缩放则保证所有"底面在 z≈0"的物体
（714/845 个都在 [0,200)）放大后**仍然精确贴地**。**不要**分步做，中间态会不自洽。

**入选规则**：

1. `find_actors("SG")` 返回的 **845** 个 actor —— 主体；
2. `find_actors("PipiWander")` 返回的 **30** 个皮皮 —— 同样按公式变换（位置 ×2、
   缩放 ×2），否则它们会留在原地、落进错误的位置；
3. `WaterZone_UAID_00163E6E452288F802_1311752325` —— 单独按同一公式变换
   （它不是 StaticMeshActor，不会出现在上面的结果里）。

**不要**用空 name 的 `find_actors`，**不要**用 `get_actor_bounds`。
